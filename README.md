# API для распознавания гаек и болтов

Приложение принимает изображение в формате JPG или PNG, находит гайки и
болты и возвращает JSON с классами, уверенностью модели, координатами рамок и
количеством объектов.

Модель состоит из детектора кандидатов и классификатора объектов. Детектор обучался на 9 485 изображениях, а сrop-классификатор обучался на 12 000 crop-изображениях.
Дополнительно для оценки детектора использовались:
validation: 1 353 изображения;
test: 731 изображение.
Было протестировано более 12 версий модели.

Датасеты для запуска не нужны. Рабочие веса уже находятся в репозитории:

```text
models/best.pt
models/classifier_best.pt
```

## Результаты на независимом benchmark

Финальная система `best.pt + classifier_best.pt` проверена на отдельном наборе,
который не использовался для обучения модели. В benchmark вошло 260
изображений: 254 размеченных болта, 371 гайка и 111 изображений без целевых
объектов.
Для "Прод"-решения лучше использовать больший и более разнообразный тестовый датасет.

### Метрики по классам

| Класс | Precision | Recall | F1-score | TP | FP | FN |
|---|---:|---:|---:|---:|---:|---:|
| Болт | 74,31% | 31,89% | 44,63% | 81 | 28 | 173 |
| Гайка | 96,98% | 52,02% | 67,72% | 193 | 6 | 178 |

### Важный нюанс

Метрики невысокие из-за их честности. При использовании разбиение одного датасета на train/val/test - они были около 0.95, но не отражали реальную картину и способность модели работать с абсолютно новыми данными. Для тестового задания считаю результат вполне приемлемым.
Для улучшения качества обнаружения и классификации объектов нужно больше данных и времени на обучение.

### Общие метрики

| Метрика | Результат |
|---|---:|
| Macro F1 | 56,17% |
| Изображения с полностью правильным количеством объектов | 52,69% |
| Доля негативных изображений с ложным срабатыванием | 5,41% (6 из 111) |
| Среднее время обработки изображения | 28,65 мс |
| P95 времени обработки | 47,78 мс |

Высокий precision показывает, что большинство найденных объектов определяются
правильно. Основное ограничение текущей модели — невысокий recall: она может
пропускать настоящие объекты, особенно на изображениях, отличающихся от
обучающих данных. Крайне редко определяет объект там, где его нет, за это отвечает негативная выборка.

## Запуск через Docker


git clone --depth 1 --single-branch --branch ready-for-inference https://github.com/Forzq/test-task.git

cd test-task
docker compose up --build


Дождитесь сообщения о запуске Uvicorn или проверьте состояние контейнера:

```powershell
docker compose ps
```

Сервис `api` должен иметь состояние `healthy`.

После запуска доступны:

- Swagger UI: <http://localhost:8000/docs>
- состояние моделей: <http://localhost:8000/health>

Успешный ответ `/health` содержит:

```json
{
  "status": "ready"
}
```

Для проверки через Swagger откройте `POST /predict`, нажмите `Try it out`,
выберите JPG или PNG и нажмите `Execute`.


Остановить приложение:

```powershell
docker compose down
```

Повторный запуск без пересборки:

```powershell
docker compose up
```

## Запуск без Docker

### Требования

- Python 3.11;
- `pip`;
- свободный порт `8000`.

Рекомендуется использовать виртуальное окружение.


Создайте и активируйте окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Обновите `pip` и установите зависимости:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Запустите API:

```powershell
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Для разработки с автоматической перезагрузкой:

```powershell
python -m uvicorn app.main:app --reload
```

## Известные ограничения и возможные улучшения

- Модель может пропускать ржавые, повреждённые, маленькие или снятые с необычного ракурса детали. Для улучшения необходимо добавить больше таких размеченных изображений и использовать hard-positive mining — собирать примеры, на которых модель пропустила настоящий объект.

- Высокие пороги уверенности уменьшают количество ложных срабатываний, но одновременно увеличивают количество пропущенных объектов. Пороги для гаек и болтов следует повторно подобрать на отдельной валидационной выборке.

- Модель иногда может принять похожий посторонний предмет за гайку или болт. Для решения этой проблемы необходимо добавлять проверенные hard-negative примеры: шайбы, винты, кольца, инструменты и другие визуально похожие объекты.

- Детектор обрабатывает изображения с разрешением 640 пикселей, поэтому очень маленькие объекты могут терять детали. Возможные улучшения — увеличение разрешения inference, обработка изображения частями или использование более крупной модели.

### Все эти ограничения решаются оптимизацией и использованием более серьезных мощностей для обучения, а также большим количеством качественных данных.
